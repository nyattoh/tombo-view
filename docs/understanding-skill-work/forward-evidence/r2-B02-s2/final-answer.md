# 進捗報告（確定版）

ユーザー指示に基づき、`pending`（まだ完了していない）と `failed`（失敗）を厳密に区別し、現存する記録（`export/snapshot.json` および `docs/fields.txt`）の範囲で処理順と進捗状況を整理した報告文です。

---

## 1. 整えた進捗報告文案

```markdown
【進捗報告：バッチ local-batch-17】（記録時点: 2026-10-19T10:00:00+09:00）

■ 処理状況
- 投入件数: 全4件（投入指定順: p1, p2, p3, p4）
- 完了件数: 2件（完了順: p1, p2）
- 未完了（pending）: 2件（p3, p4）
- 失敗（failed）: 0件

■ 処理順および進捗の記録
投入された全4件のうち、現時点で記録されているのは投入順の先頭2件（p1 → p2）が順番通りに処理完了した状態です。
残りの2件は処理待ち（pending）として継続中であり、確定した処理失敗（failed）は発生していません。
本スナップショットは途中経過の記録であり、全件完了ではありません。
```

---

## 2. 下書きからの訂正内容の詳細
- **pending と failed の区別**:
  - `docs/fields.txt` の定義に基づき、pending は「受付済みだが処理がまだ完了していない件数」であり、確定した失敗（failed: 0件）とは明確に区別されます。
- **処理順の記録範囲**:
  - `export/snapshot.json` に記録されている処理順は `completed_order: ["p1", "p2"]` のみです。
  - 投入時の指定順（`published_order: ["p1", "p2", "p3", "p4"]`）の通りに先頭2件が完了していることが確認できます。全4件の処理が完了したかのような表現を改め、現時点で確認できる範囲（2件完了・2件未完了）に限定して記述しています。

---

## 3. スキル・SDK状態の記録
- **TOMBO 状態**: revision 3 において時間予算超過（`maxElapsedMs: 300000ms` に対し実経過 `366422ms`）により `stopReason: budget_exhausted`（`decision: blocked`）で停止しています。
- 会話上の分析・報告文の整形は完了していますが、SDK内部の自動状態遷移は時間予算上限により停止・維持されています。
