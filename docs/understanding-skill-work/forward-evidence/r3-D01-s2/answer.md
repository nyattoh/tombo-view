# 検討結果と改訂版開発報告用説明文

## 1. 電源設定メモ（notes/power-settings.txt）を踏まえた検討結果

**「まとめ書きへの変更で処理が約1.5倍速くなった」と断定して開発報告に記載することは不適切（根拠不十分）です。**

### 根拠と判明した事実（観測事実）
1. **環境条件の交絡**:
   - `notes/power-settings.txt` により、午前の `before` 測定時はOSの電源モードが「省電力」、午後の `after` 測定時は「高パフォーマンス」に切り替えられていたことが判明しました。
   - したがって、測定時の条件差はコード変更（まとめ書き化）だけでなく、OSの電源設定の変更が同時に発生していました。
2. **要因の未分離**:
   - 同一電源モードに揃えた `before` と `after` の測定記録は存在しません。
   - コードを変更せずに電源モードのみを切り替えた測定記録も存在しません。
   - CPU動作周波数・消費電力・ディスク待ち時間等の詳細メトリクスは記録されていません。
3. **結論**:
   - 観測された約1.5倍の所要時間短縮（12.0秒→8.0秒）のうち、どれだけがまとめ書き化による効果で、どれだけが電源モード変更による効果かを分離できません。
   - したがって、「まとめ書き変更単独の効果として約1.5倍高速化した」という主張は支持されません。

### 留意事項・限界（理解の再考）
- 電源モード変更が所要時間に与えた具体的・定量的な寄与率は未計測であり、代替原因の寄与量を勝手に確定・誇張（「電源モードのせいだ」等）することはできません。
- あくまで「2つの要因が混在しており、現有データではまとめ書き単独の効果を特定できない」という事実のみを扱います。
