# Hidden-Side Observation

Hidden-Side is an optional retrieval comparison alongside TOMBO's existing lens, gap and probe workflow. It searches a caller-supplied candidate corpus from the current viewpoint and from directions derived from a local context subspace. It does not replace evidence assessment, reflection, or the existing `inspect` / `update` / `reflect` operations.

## Boundary and terms

- **Context Surface**: the linear subspace spanned by caller-supplied context embedding rows. Each non-zero row is normalised before a twice re-orthogonalised modified Gram-Schmidt pass. Dependent rows do not increase the rank. The current implementation does not centre the rows; this is a linear subspace through the origin, not an affine plane.
- **Viewpoint Vector**: the embedding supplied for the current question or search purpose, generated by the same embedding model as the context and candidate vectors.
- **Hidden-Side Direction**: either the orthogonal residual `r = v - P(v)` or the reflected query `v_hidden = P(v) - r`, where `P(v)` is the projection onto the Context Surface.
- **Occluded Candidate**: a candidate whose rank enters the selected hidden-side top-k while it was outside the Similarity top-k. This is rank-based retrieval visibility only; it is not geometric occlusion or proof of relevance.
- **Observation Evidence**: this module's result includes source locator, rank, cosine score where defined, embedding model label, context digest and `unverified` status. A retrieval result alone is not a TOMBO `Evidence` item and cannot support or resolve a claim.

The CAD correspondence is an analogy. A subspace normal is generally not a unique vector in high dimensions. Back-face orientation and hidden-surface occlusion are distinct in CAD; neither is reproduced by this ranking operation.

## Retrieval methods

`compareHiddenSideMethods` accepts the context/viewpoint text, same-model vectors, candidate IDs/concepts/sources, and returns method rankings plus comparison rows. It also records each candidate's rank and cosine score against the equal-weight mean of unit context vectors; this is a descriptive context-contact measure, not a relevance judgement. It normalises the viewpoint vector before projection; the projection/reflection ranking is invariant to positive scaling. The observation includes projection, residual and reflected-vector norms so callers can inspect the numerical geometry.

- `similarity`: cosine ranking by the original viewpoint vector.
- `orthogonal`: cosine ranking by the residual component; it is undefined and rejected when the residual is zero.
- `reflected_view`: cosine ranking by `P(v) - r`.
- `random_baseline`: deterministic pseudo-random ordering from a SHA-256 hash of `(seed, candidate ID)`, independent of candidate input order; it is not a diversity optimiser and its uniformity is not statistically validated.

For every hidden-side method the result records the Similarity rank, method rank, rank gain, top-k intersection and overlap ratio. Candidate score is nullable for random order or zero candidate vectors. Interpretations are always `null` and verification is always `unverified` at this stage. The caller must not compare vectors from different embedding models or versions; the library receives vectors and does not produce embeddings, search services, or provenance proofs.

The API is opt-in and does not modify TOMBO's task packet, state schema, CLI commands, or standard skill workflow. In combined mode, surfaced candidates can inform an `unexplored_view` gap or a probe proposal; only a separate, authorised retrieval/read/test can return source evidence for ordinary TOMBO assessment.

## First fixed-corpus experiment

Run `npm run hidden-side-demo`. It uses the fixed context `犬、カレー、夕暮れ、帰宅`, the viewpoint `家庭での食事`, a 28-item synthetic corpus, and a transparent local Unicode character 1–3-gram hash vectoriser. All four rankings use that same vectoriser and candidate set. The script writes `evaluation/hidden-side-example.json`, prints each top 10, and makes no paid or external calls.

This is a deterministic feature-vector smoke experiment, not a semantic embedding comparison. It can verify the ranking math and show rank changes for this fixture only. It cannot establish that surfaced concepts are meaningful, that a semantic embedding model finds useful hidden-side candidates, or that TOMBO improves over another RAG method. A next semantic experiment needs an explicitly selected, authorised embedding model; a sufficiently large fixed corpus with source locators; frozen scoring and relevance annotations; and identical model/version and candidate set across methods. Until that exists, semantic retrieval and effectiveness remain unverified.

### Recorded result for the supplied input

The run produced context-surface rank 4, viewpoint projection norm 0 and orthogonal-residual norm 1. In this local character-feature representation, the viewpoint was orthogonal to the entire context subspace, so Orthogonal and Similarity returned the same top 10. Reflection therefore became the negated viewpoint; its top 10 were `帰宅後に犬が迎える`, `朝食を作る`, `夕暮れに帰宅`, `カレー皿`, `スープを温める`, `夕方の散歩後にカレーを作る`, `カレーの買い出し`, `犬と過ごす休日`, `夕暮れの散歩`, and `帰宅時の玄関`. Their Similarity ranks were 24, 25, 26, 27, 28, 23, 22, 21, 19 and 20. Top-10 overlap was 100% for Orthogonal, 0% for Reflected View, and 40% for Random Baseline; six Random Baseline candidates entered the top 10 from outside it. The context-centroid ranks for the first five reflected candidates were 3, 24, 1, 2 and 23, showing that low similarity rank and context contact can differ in this feature representation. These are measured ranks from the named local vectoriser and fixed synthetic corpus only. They do not establish that the candidates are semantically useful hidden concepts. All candidates remain unverified. The complete method top-10 records, scores, context ranks and source IDs are in `evaluation/hidden-side-example.json`.

### English

**Purpose and position.** Hidden-Side may surface candidate phrases that ordinary similarity ranks low and pass them only as unverified probe/viewpoint suggestions into TOMBO's existing evidence-check workflow. It does not create or resolve claims or evidence. A low rank is not a discovery.

**Method.** One request to OpenAI `text-embedding-3-small` embedded 33 strings (282 tokens). The candidates were a synthetic fixed 28-candidate corpus (the same context, viewpoint and candidate set as the fixed example above). Similarity, Orthogonal, Reflected View and the deterministic Random Baseline were compared over the same vectors and candidate set.

**Measurements (this single run only).**

- Context-surface rank 4; viewpoint projection norm 0.437; residual norm 0.900.
- Top-10 overlap with Similarity: Orthogonal 10/10, Reflected 0/10, deterministic Random 3/10.
- Similarity ranks of the Reflected candidates: 24, 18, 21, 23, 16, 15, 22, 19, 14, 26.
- All candidates are `unverified`.

**Geometric interpretation.** For unit `v`, `p = P(v)` and `r = v - p`: `cos(r, v) = ||r||` and `cos(p - r, v) = 2||p||² - 1`. Here the cosine between the reflected query and the viewpoint is about -0.62. When the projection norm is below `1/√2`, the reflected direction points opposite the current viewpoint. Reflected candidates are therefore low-similarity candidates, not discoveries.

**Not independently reconstructible.** The figures above are a summary of metadata and aggregates. Per-candidate live rankings are not published, so exact ranks cannot be independently reconstructed or verified from this repository.

**Input provenance.** The context, viewpoint and candidate set fed to Hidden-Side's vector search are all prepared and supplied by the caller. This optional branch returns only unverified candidates and probe/viewpoint suggestions, which flow back solely into standard evidence verification.

**What this run cannot show.** With no human relevance ratings, it shows nothing about the semantic usefulness of the candidates, detection ability, generalisation, or superiority over other RAG methods. The fixed n-gram example above (`evaluation/hidden-side-example.json`) is not this live embedding result. The full raw result is ignored local `.audit` data (not tracked by git) and is not published.

**Comparison with CrossRAG.** CrossRAG's Orthogonal score is a blend (0.42 band, 0.38 orthogonal, 0.20 relevance/coherence); TOMBO's is the pure projection-residual cosine. The two scores are not equivalent and must not be compared or ported across. CrossRAG's Wedge expects ordered candidate pairs, whereas TOMBO candidates are single phrases, so TOMBO Wedge remains unimplemented.

## Numerical behaviour

The implementation has no numerical dependency. It validates finite, equal-dimension, non-empty vectors; normalises non-zero context rows and the viewpoint; uses a fixed `1e-10` residual tolerance by default; and uses a re-orthogonalised modified Gram-Schmidt basis. Zero context rows are ignored. If no non-zero context direction remains, similarity/random-only comparisons remain available but a requested orthogonal/reflected search throws `zero_context`; context-derived geometry norms are null. A zero viewpoint, dimension mismatch, malformed input, or requested orthogonal search with no residual also throws a typed error. A reflected search remains valid if the viewpoint lies wholly inside a non-empty surface; in that case reflection equals the original vector. Zero candidate vectors have undefined cosine, so their cosine rank, context rank and rank gain are `null`; they are excluded from cosine top-k overlap denominators. Comparison rows expose `baseline_scored` so an unscorable vector is distinguishable from a scored candidate outside the baseline top-k. Random ordering still gives every candidate a random rank.

The basis method is intended for the small context sets in this optional feature. It is not a general-purpose high-performance SVD implementation. Wedge retrieval, centring alternatives, learned diversity, ANN indexing and external embedding adapters are not implemented.
