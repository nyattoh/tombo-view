# メタ認識を確かめる開発計画

利用者は、TOMBOが理解の盲点を探し、反証で判断を修正し、不明事項を保持する目的を果たすまで継続開発することを承認した。この計画は全ての未知の発見や、モデル内部の理解の直接観測を保証するものではない。

## 完了判定

1. 調査前に、主張・不足・支持条件・反証条件・次の検査が記録される。候補と証拠評価は実際のAIが生成する。
2. 初期の点検で必要な確認がないとされた場合でも、別の観点を探す再考を実行できる。再考は証拠そのものとして登録せず、新たな検査候補として扱う。
3. 必要な検査を呼出し元が明示した能力だけで実行し、反証により主張と未確認事項を更新する。資料不足、利用不可、矛盾、予算不足を解決へ変換しない。
4. 上記の実行経路、再試行、利用量、証拠撤回と再考の寿命を公開API・CLI・スキルで回帰検証し、独立レビューが合格する。
5. 通常の再点検とTOMBOを同じモデル・資料・利用可能な検査・要求上限で比較する。評価注釈を参加モデルへ渡さず、繰返しを独立ケースとして数えない。
6. 対象範囲での盲点発見・判断修正・正しい不明保持・不要な検査を独立に評価する。全て不明として終了する方式は合格にしない。失敗・欠測・未実行を分母から落とさない。

比較評価の数値基準は、評価器の実装段階でprotocol.jsonへ固定し、参加モデルの結果を見る前にコミットする。初回の開発用パイロットは評価用の成績として報告しない。評価結果で基準を緩めて完了としない。

## 実行順序

- 計測器を先に作る。既存48件は論点を直接示す短い架空シナリオであり、それだけで盲点発見能力を測ったとは扱わない。資料・検査結果と非問題の対照を含むケースを追加する。
- コアに再考を追加する案と、外側の実行ループに再考を持つ案を独立に比較する。状態の正本と会計を二重化しない案を選ぶ。
- 再考と検査実行を小さな単位で実装する。単位ごとに失敗例を先に再現し、実行検証後に次へ進む。
- パイロットで計測器と実モデルの接続を確認する。評価用データは改善の入力に使わず、固定した条件で比較する。
- 見つかった不足を根因から修正する。最終的な効果は実行された比較結果に限定して記述する。

## 並行作業と費用

設計二案は読取りと各自の成果物だけを担当する。評価器と製品実装は所有ファイルを分ける。親が統合、比較実行と独立判定、スキル導入、公開PRを管理する。

追加の有料生成APIとJevは呼ばない。前回許可された50円を、今回の不明なAPI費用へ自動的に振り替えない。ホストの委任モデルの費用・トークンが取得できない場合は不明と記録し、金額上限を保証したとは扱わない。

判断記録の正本はdocs/metacognition-decisions.tsvとする。内部の思考過程や生の会話を保存しない。元のコード、既存評価データと以前の停止・失敗記録を保持する。
